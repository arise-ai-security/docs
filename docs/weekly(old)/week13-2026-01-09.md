## Blocked: Research Question

We observed that simple changes in system prompts can drastically alter system output. This may apply to all AI agent-related research. Our approach is to iterate on the system prompt until we achieve an optimal configuration, then treat it as fixed while adding other features.

**Research Questions:**
1. How do we define criteria for an "optimal" system prompt? Are there established standards in AI agent research for this?
2. Is there a de facto standard for treating system prompts as control variables? 

### Example: Prompt Sensitivity

The following prompt creates complex trees with more than 300 nodes:

```text
### SIMPLE (Execute directly, Default)
- Task has numbered prefix (e.g., `[Step-1]`, `[Task-2]`) - already decomposed
- Single clear action with known steps
- Changes confined to 1-2 files
- All required context is provided
- Clear implementation path

### COMPLEX (Decompose into parallel subtasks):
- Everything other than SIMPLE is COMPLEX
```

However, the following creates overly simple 2-layered trees (all else unchanged):

```text
### SIMPLE (Execute directly, Default)
- Task has numbered prefix (e.g., `[Step-1]`, `[Task-2]`) - already decomposed
- Single clear action with known steps
- Changes confined to 1-2 files
- All required context is provided
- Clear implementation path

### COMPLEX (Decompose further)
- Multiple distinct operations needed
- Spans 3+ files or modules
- Ambiguous requirements
- Requires exploration before execution
- Architectural decisions needed
```

**Conclusion:** If a small prompt edit swings results this much, there may be little value in changing other features until we lock the prompt.

## Key Analysis of Worker Behavior

### Key Findings

Most vague prompts involve file reading, web searching, or downloading operations (git pull, git clone, curl, etc.).

1. **40%** of workers received vague or semi-vague tasks.
2. Vague prompts cost **72% more tokens** than unambiguous ones.
3. Vague prompts cause **50% more tool calls** and iterations.

**Common Vagueness Patterns**

- "analyze ..."
- "identify ..."
- "review ..."
- "document ..."

## Proposed Solution

1. Perform information gathering in Manager nodes and use the results as additional context for decision-making.
2. Restrict Workers from executing vague operations via tool calls.

### Researcher Node

A dedicated node for tool-calling operations. It retrieves data from tools and stores it in context to pass to other nodes.

### Worker Restriction List (WIP)

Apply allowlist and blocklist restrictions to Workers:

```text
blacklist:
  - web_search
  - web_fetch
  - git_pull
  - git_push
  - curl
  - wget

whitelist:
  - read_file
  - write_file
  - execute_code
  - list_directory
  - git_commit
  - git_diff
```
