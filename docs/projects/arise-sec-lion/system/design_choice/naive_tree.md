# Design Choice 1: Recursive Planning and Working With No Constraints
This page analyzes the direct approach to implement the tree-structure with only 2 models (GPT-4o and GPT-4o-mini) without additional restraints. Agents decide to become worker agent nodes or spawn more subordinate agent nodes all at the internal LLM's discretion.

## Naive Tree-Structured Agentic System 
This system is not incorporating any extra features such as budget management, task assignment mechanism, or reward allocation mechanism. Each agent node simply spawns subordinate nodes to tackle sub-tasks without any constraints or monitoring.

## Case Study Task
### Task Objective
Use python 3 to write a multi-threading script called keyword-find-fast. on terminal, when python keyword-find-fast -r kekasdf is called it recursively looks into every single file in the current directoty and print out the full file path with that keyword in red.

### Analysis
1. **Tree Growth**: The tree structure grew rapidly as each agent spawned multiple subordinate agents without any constraints, leading to a large number of nodes. In this system, agents quickly proliferated and most of them become thinking nodes.
2. **Deep Thinking to Overthinking**: In the original design, agents are encouraged to explore and think deeply about the task. For example, even for simple tasks like writing into a file, agents would spawn multiple thinking nodes to deliberate on the best approach. However, most questions do not have concrete answers and excessive thinking leads to overthinking, which wastes resources and time. For example, in this case study, one agent even tries to do online research: "Manager: Conduct a literature review to identify recent academic publications on context capturing techniques." Agents are overly conservative about their own internal knowledge.
3. **No Branch Pruning**: Since there is no budget management or task assignment mechanism, there is no way to prune unproductive or excessively large branches of the tree. For example, features like logging is overly implemented but it's effect plays insignificant part in the over objective achievement. This system relies execlusively on internal LLM's understanding of task decomposition, which is likely to be theoretically correct but practically unnecessary. A better task assignment mechanism should be enabled to help to allocate tasks more efficiently and avoid redundant work.
4. **No Seperation of Responsibilities**: In this current implementation, all of agents have full view and edit access to all files in the coding environment. This works when the supervisor nodes are able to seperate and design sub-tasks cleanly without no inter-dependency. However, for a larger project, the lack of access controls can cause file-editing race condtions, repeated work, or conflicting changes. A better approach should include file locks to ensure that only one agent can edit or use a file with permissions.
